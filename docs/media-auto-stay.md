# 媒体播放时不自动离开

开关位于设置的“记录与时间 → 离开判定”，默认开启。旧设置载入时仅补充这个新默认项，原有设置值不变；用户关闭后会保存关闭状态。

默认模式和不识屏模式下，每 5 秒在后台检查 Windows 媒体会话。如果会话处于 Playing，且播放来源匹配前台应用，则更新独立的媒体活动时间。空闲倒计时以真实输入、手动恢复记录和媒体活动中最近的一次为起点，空闲阈值保持原样。不识屏模式仍停止截图和识别，原有持续时间也不延长。

媒体类型不参与判定：Chrome、PotPlayer 等应用可能把视频上报为 Music，所以视频和音乐都可以保持记录。优先匹配完整 AppUserModelID，其次匹配完整进程名称（允许 `.exe` 后缀及大小写差异），不通过标题、部分名称猜测来源。无法匹配的来源不生效。

暂停、结束、前台应用不匹配或读取失败时停止刷新，沿用正常空闲倒计时。关闭开关同样保留最后一次有效活动起点，不立即强制离开。手动离开、关闭自动记录、系统锁屏、休眠均优先；媒体不会把离开模式自动恢复，恢复仍依赖真实输入。显示桌面时自动离开的 5 秒规则也保留。

这是应用层面的匹配：同一浏览器的后台标签页或其他窗口播放，也可能被计入；画中画或副屏播放时，若所属应用不在前台则不生效。

## 构建注意事项

为调用 Windows 媒体会话 API，Windows 层和桌面层的编译目标改为 `net10.0-windows10.0.19041.0`，开发启动脚本已同步新的输出路径。版本号由原有构建流程控制，本项不设置版本号。

编译 SDK 目标与最低系统声明分开，保留原来的最低系统声明；媒体 API 在 Windows 10 1809 之前不启用，读取不可用时回到正常空闲判定。此处不意味着 .NET 运行时支持所有旧 Windows。

构建输出增加 Windows SDK 的托管投影及 WinRT 运行库（`Microsoft.Windows.SDK.NET.dll`、`WinRT.Runtime.dll`）。打包时应保留 publish 输出的完整依赖；现有单文件发布由 .NET 处理这些依赖，不应自行遗漏或删除。
