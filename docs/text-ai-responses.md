# 文本 AI 响应限制与故障诊断

时段摘要、总结和总结后续对话使用相同的文本请求规则。原有的首内容 2 分钟、内容空闲 60 秒、总计 5 分钟超时规则保留；服务明确不支持流式时，非流式重发仍为 120 秒，并受整个请求 5 分钟期限限制。

## 大小限制

原来的 2 MB 限制把整个流式响应计在一起，包括重复 JSON 字段、思考和正文，可能在正文很短时就中断。现在拆为：

| 数据 | 上限 | 计算方式 |
| --- | --- | --- |
| 正文 | 2,000,000 字节 | 解码后正文的 UTF-8 字节数 |
| 思考 | 8,000,000 字节 | `reasoning_content` 和 `reasoning` 两个字段的 UTF-8 字节数之和 |
| 整个文本响应 | 64,000,000 字节 | 接收的原始响应数据，包含 JSON、SSE、保活注释等 |
| 单行或单个 SSE 事件 | 16,000,000 字节 | 防止没有换行或没有事件边界的数据持续占用内存 |

MB 为十进制。正文和思考独立统计，流式包装不消耗正文限额。服务直接返回 JSON 或明确拒绝流式后退回非流式，也应用相同的文本预算。截图识别仍沿用原来的 2 MB 响应限制。

思考不会作为摘要正文显示或存入成功结果。达到大小限制时会中止该次响应，具体错误会区分正文、思考、整个传输或单个事件；不会把不完整结果当作成功结果。现有自动重试规则保留，大小超限仍需要手动重试。

## 本机故障报告

失败时在数据目录的 `Logs` 中创建 `text-failure-*.html`，保留最近 40 份报告。索引为 `text-failures.html`，可从时段摘要、总结和对话失败处的“查看故障详情”打开。

每份报告记录总结 ID、分批调用或对话 ID、实际请求的接口和模型、错误原因，以及以下有限信息：

- 已接收传输、正文和思考的字节数，流式事件数及已收到的 `finish_reason`。
- 正文、思考、原始响应和服务错误详情各自最前与最后 2048 个 UTF-16 代码单元，中间省略并标注。
- 捕获的诊断文本合计小于 64 KiB；写入 HTML 时转义显示，并隐藏本次使用的 API Key。

报告只保存在本机，可能包含活动相关文字。不会额外保存发送的完整提示词、截图或请求头。日志写入失败不会改变任务原来的错误或重试处理，原有截图识别故障报告不会被文本日志清理删除。

用户主动取消任务不产生文本故障报告。旧版本没有保存的失败输出无法通过更新恢复；应在更新后再次发生失败时查看新报告。
